Tenveo PTZ Camera — Full Guide

Everything you need to set up, operate, colour-grade and troubleshoot the front-of-house PTZ camera. Start with the Quick Start if you just need it running; use the reference sections below when things go sideways.

⚡ Quick start

If everything is where it was last week, this is all you need. Aim for 20 minutes end to end.

  1. Set up the tripod at the front of house. Splay legs, lock centre spreader, extend column to just above seated eye-line.
  2. Clip the camera onto the tripod using the quick-release plate. Engage the safety lever — tug the camera gently to confirm it's locked.
  3. Power the camera — plug the 12V adapter into a wall socket and into the camera. Wait 30 seconds. The lens will motor-initialise (pans, tilts, focuses). Front LED comes on.
  4. Plug the camera into the Starlink router — Ethernet cable from the camera's LAN port into any free LAN port on the router.
  5. On the Mac Mini — open OBS. The NDI source for the camera should still be there from last week.
  6. Verify the feed appears in OBS preview. If yes → you're done. Frame the shot per Camera framing.
✓ If it just works

Great. Set your Presenter preset (see AI auto tracking), confirm the LUT is applied for colour, and you're ready for service. Total time: about 15 min.

⚠ If NDI source is missing from OBS

The camera might be on a different IP than last time — routers sometimes reassign. Jump to OBS connection to re-add the source. If OBS shows "no NDI sources found", check Network setup.

✗ If nothing works today

Fall back to phone camera immediately — that setup is proven and covers every Sunday. Fix the PTZ mid-week when there's no time pressure. Sunday service always wins.

Why so many cables?

There are three ways to get video from the camera to the streaming computer: NDI (over Ethernet), USB, or HDMI to a capture card. We use NDI as primary because it needs one cable and gives us remote control from the same connection. USB and HDMI are proven fallbacks — this is why we keep the extension cable and HDMI cable to hand.

2 Network setup

The trickiest part of the whole system. Read this section once, refer back to it whenever things break.

How it's currently wired

  • Camera → Ethernet cable → Starlink router (any LAN port)
  • Mac Mini → Ethernet cable → Starlink router (the other LAN port)
  • Mac Mini also on Starlink Wi-Fi for internet

The important bit — IP addresses

The camera ships with a factory IP of 192.168.0.206. Starlink's network runs on the 192.168.1.x range. These are different networks, so by default the camera and the Mac Mini can't see each other.

The workaround we use: the Mac Mini's Ethernet is set to a manual IP on the camera's network, so it can reach the camera directly. Its Wi-Fi stays on Starlink for internet.

Two networks at once, no conflict

The Mac Mini lives on both networks simultaneously — Wi-Fi for Starlink (internet), Ethernet for the camera. macOS handles this fine as long as Wi-Fi is the primary service (top of the list in Network settings).

How to check / restore these settings

  1. Apple menu → System Settings → Network
  2. Click Ethernet → Details…
  3. Click TCP/IP in the sidebar
  4. Confirm Configure IPv4: Manually, IP Address 192.168.0.100, Subnet Mask 255.255.255.0
  5. If not, change them, click OK, wait 5 seconds
  6. Test by opening a browser and going to http://192.168.0.206 — should get a login page

Confirming the camera is reachable

Open a browser on the Mac Mini and visit http://192.168.0.206. You should see the Tenveo login page. Login with admin / admin.

If the login page won't load

The camera and Mac are on different networks. Either the manual IP was wiped (redo the steps above) or the camera has drifted to a different IP. Try arp -a in Terminal — you'll see every device the Mac has heard from.

3 OBS connection

How the camera feed gets from the network into OBS. Once set up, this is set-and-forget.

What OBS needs (one-time setup)

  • OBS Studio — the streaming software itself
  • DistroAV plugin — makes OBS understand NDI sources
  • NDI Runtime — background service that finds NDI sources on the network

All three should already be installed on the Mac Mini. If the "NDI Source" option is missing when you click + in OBS Sources, one of them isn't loaded — usually the NDI Runtime. Download it from ndi.video/tools and reinstall.

Enable NDI on the camera

Log into the camera web interface (http://192.168.0.206). In the left sidebar, click NDI Settings. Make sure NDI output is ON. Save.

Add camera as source in OBS

  1. In OBS Sources panel → click + → choose NDI Source
  2. Name it "Tenveo PTZ" → OK
  3. In properties: Source name dropdown → pick the Tenveo entry (looks something like TENVEO (Channel 1))
  4. Set Bandwidth to Highest
  5. Set Sync to Network
  6. Click OK — camera feed appears in preview
Source name dropdown is empty

Either NDI isn't enabled on the camera (see above), or the Mac Mini can't reach the camera's network (see Network setup). NDI is auto-discovered — if it's not showing up, the network path is broken.

4 Camera control

How to move the camera and save preset positions.

From the Mac Mini web interface

Open http://192.168.0.206 and log in. On the right side you'll see a joystick — arrows for pan/tilt, buttons for zoom in/out. Move the camera live.

Setting a preset (recommended before service)

  1. Move the camera to the position you want (e.g. pulpit, framed head-to-waist)
  2. Click the preset slot (usually numbered 1–9)
  3. Click Save or long-press the slot
  4. To recall later: click the slot number → Call

Useful presets for a standard service:

PresetPosition
1Presenter — pulpit, head to waist
2Worship team wide — full stage
3Congregation wide — from stage looking back
4Choir / musicians close

From the IR remote (backup)

The remote in the camera box works if the network drops. Point it at the camera, use the D-pad. Works line-of-sight only — no obstructions.

Phone control — not yet

Right now the camera can only be controlled from a device on the 192.168.0.x network — that means the Mac Mini. To let phones on Starlink Wi-Fi control it, we'd change the camera's IP to 192.168.1.206. Planned for later; leave it for now to avoid breaking what works.

5 AI auto tracking

Follows the preacher automatically. Configured properly, this replaces having a dedicated camera operator.

The three modes

ModeBehaviourUse for
AutoFramingDetects everyone in shot, zooms out to fit them allMeetings, panels — NOT what we want for church
PresenterLocks onto one person, follows them at fixed zoomPreacher on stage ← this is what we want
OffManual control onlyTesting, framing setup

Setting up tracking properly

  1. In the web interface, click Tracking in the sidebar
  2. Set Mode to Presenter (not AutoFraming — AutoFraming zooms out constantly)
  3. Manually zoom in first to your desired framing (head to waist). Use the joystick + zoom controls.
  4. Set that as the Presenter preset (click Preset 1, save)
  5. Uncheck Auto Zoom — keeps the zoom level fixed once tracking starts
  6. Uncheck Auto Tilt — keeps the vertical framing consistent
  7. Set Target Retention Time to 6 seconds — how long the camera waits before releasing a lost subject
  8. Toggle Track: ON — tracking is now live
Why zoom in BEFORE enabling tracking

If you enable tracking first, it starts from wide and never comes in. Frame first, save the preset, then enable — the camera locks in at that framing and follows the preacher without changing zoom.

When tracking goes wrong

  • Camera keeps zooming out → Mode is set to AutoFraming instead of Presenter. Change it.
  • Camera follows the wrong person → Untick tracking, reframe on the correct person, save preset, re-enable.
  • Camera locks up mid-service → Toggle Track OFF then ON. If persists, fall back to preset recall.

6 Colour treatment (LUT)

The cinematic look — applied in OBS on top of the camera feed. Same LUT used by Twelfth Collective.

Why we use a LUT

The camera produces a neutral image. A LUT (Look Up Table) applies a colour grade — like a filter on Instagram, but purpose-built for video. It gives every service a consistent, warm, cinematic feel that matches the sermon clips we post online.

Where the LUT file lives

The .cube file is in Google Drive. On the Mac Mini it should already be in Downloads from the first setup. If it's missing, download again from Drive.

Applying the LUT in OBS

  1. In OBS, right-click the Tenveo PTZ source → Filters
  2. Under Effect Filters, click + → Apply LUT
  3. Click Browse, navigate to Downloads, select the Twelfth .cube file
  4. Set Amount to 60-75% (100% is usually too strong)
  5. Preview updates immediately — adjust to taste
Amount slider guide

40-50% — subtle, natural. Good if room lighting is already warm.
60-75% — our default. Cinematic without being obviously graded.
90-100% — heavy, saturated. Only for artistic moments.

Camera-side settings (bake in first)

Before adding a LUT, get the camera producing a clean image. In the web interface → Image tab:

  • White Balance — set to Manual, tune for the room's lighting (usually 4500-5500K for church halls)
  • Exposure — Auto is fine unless lighting changes dramatically
  • Backlight Compensation — ON if the preacher stands in front of bright windows
  • Wide Dynamic Range (WDR) — ON for mixed lighting

Then let OBS handle the "look" via the LUT. This is how it's done professionally — camera gives a clean baseline, software adds the grade.

7 Sunday run-through

Copy-paste this checklist for every Sunday. Aim to be done 20 minutes before service.

90 minutes before service (9:00 arrive, 10:30 service)

  1. Tripod set up at front of house, camera clipped on, secured with QR safety lever
  2. Power the camera — 12V adapter into wall + camera. LED comes on. Lens motors initialise.
  3. Ethernet cable from camera to Starlink router (LAN port)
  4. Mac Mini awake, Ethernet plugged in, Wi-Fi on Starlink
  5. Open OBS, confirm NDI source shows the camera feed in preview

60 minutes before service

  1. Frame the shot — Presenter preset. Head-to-waist on the pulpit. Test with someone standing in position if possible.
  2. Set/verify tracking — Mode: Presenter, Auto Zoom OFF, Auto Tilt OFF
  3. Confirm LUT is applied in OBS (Filters on the source) — image should have the warm cinematic look
  4. White balance check — the room lights will be on now; adjust if colours look off

20 minutes before service

  1. Livestream connected and confirmed live on YouTube
  2. Test switch to camera scene in OBS — projector shows camera feed
  3. Nudge/reframe if needed
  4. Preset recall test — jump to preset 2, 3, back to 1 — confirms preset system works
  5. Do not touch anything else — you're ready
If something breaks 20 min before

Switch to phone camera. It's proven, no configuration needed. Better to have a working phone stream than a fighting PTZ stream during service. Debug the PTZ mid-week.

8 Camera framing

The rules that make our stream look like a broadcast, not a security camera.

✓ Good framing
• Tight headroom — 2 to 5cm gap at top of frame
• Eyes in the upper third of the screen
• Speaker fills most of the frame
• Speaker centred or on rule-of-thirds line
• Clean background — no clutter behind the head
✗ Common mistakes
• Too much space above head (looks amateur)
• Speaker too small in frame
• Head cropped at the top
• Speaker off to one side
• Distracting elements behind (like doors opening)

Standard shot sizes

ShotFramingWhen to use
Head & shouldersTop of head to just below collarSermons — most intimate, best for online viewers
Head to waistOur default — top of head to belt lineSermons, announcements — allows some hand gesture
WideFull body plus contextWorship team, altar calls, group moments
Very wideWhole stageOpening shot, congregation moments

? Troubleshooting

The full list of what's gone wrong in the past and how we fixed it.

Camera won't power on

  • Check the 12V power adapter is plugged in at both ends and the socket is live
  • Check the barrel connector is fully seated in the camera
  • Try a different wall socket
  • If using PoE instead: check the PoE injector's power LED is on, and the camera is connected to the "POE OUT" port (not "LAN IN")

Camera powers on but no LED on Ethernet port

  • Check both ends of the Cat6 cable click into place
  • Try a different port on the Starlink router
  • Try a different Cat6 cable — we have spares in the 5-pack
  • Confirm the router LAN ports are actually active (some are labelled but disabled)

Can't reach the camera at 192.168.0.206

  • Confirm Mac Mini Ethernet is set to IP 192.168.0.100, subnet 255.255.255.0, Configure IPv4: Manually
  • Confirm Wi-Fi and Ethernet are both showing "Connected" in Network settings
  • Run arp -a in Terminal — look for any device on 192.168.0.x. If none, the camera isn't broadcasting on this network.
  • Try loading http://192.168.0.206 — if browser says "Not private", click Advanced → Proceed. Self-signed cert is expected.

NDI source missing in OBS

  • Fully quit OBS (Cmd+Q) and reopen — plugins only load at startup
  • Confirm NDI Runtime is installed — download from ndi.video/tools
  • In OBS: Sources → + → check "NDI Source" is in the list. If missing, DistroAV plugin isn't loaded
  • Log into camera web interface, confirm NDI is set to ON

NDI source appears but preview is black

  • Double-click the NDI source → Bandwidth: Highest, Sync: Network
  • Delete the source and re-add it — sometimes cached state gets stale
  • Test the camera outputs video via HDMI to a monitor — if HDMI works, it's an NDI/network issue, not the camera

Camera zooms out when tracking is on

  • Tracking Mode is set to AutoFraming. Change it to Presenter.
  • Uncheck Auto Zoom and Auto Tilt
  • Zoom in first, save preset, THEN enable tracking

Colour looks wrong / washed out

  • Check white balance in the camera web interface (Image tab) — set to Manual and match room lighting
  • Check the LUT is applied in OBS and Amount is 60-75% (not 100%)
  • If LUT file is missing, re-download from Google Drive → OBS Filter → Browse to it
Everything broken, service in 20 min

Switch to phone camera. Non-negotiable. The PTZ is an upgrade, not a requirement. Sunday service always runs — fix the PTZ mid-week when there's no time pressure.

📖 Glossary

Every jargon term used in this doc, in plain English.

PTZ
Pan, Tilt, Zoom. A camera that can move and zoom remotely.
NDI
Network Device Interface. A protocol for sending video over a network. Auto-discovers on the local network.
NDI Runtime
Background software that makes NDI work. Required alongside the OBS plugin.
DistroAV
The OBS plugin that adds NDI support. Was previously called "obs-ndi".
OBS
Open Broadcaster Software. The streaming app the church uses.
PoE
Power over Ethernet. Delivers power and data through one cable.
IP address
The unique number that identifies a device on a network. Looks like 192.168.0.206.
Subnet
A network segment. Two devices can only talk to each other if they're on the same subnet.
DHCP
Automatic IP address assignment. The router hands out addresses to devices that ask.
UVC
USB Video Class. Standard that makes a USB camera work as a webcam without drivers.
LUT
Look Up Table. A file (.cube) that applies a colour grade to video.
QR plate
Quick Release plate. The metal plate that clips the camera onto the tripod.
Auto-tracking
Camera uses AI to detect and follow a person automatically.
AutoFraming
A tracking mode that adjusts zoom to fit everyone in shot. NOT what we want.
Presenter mode
A tracking mode that locks onto one person at fixed zoom. What we DO want.
